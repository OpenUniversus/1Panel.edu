048 个值得抄的设计

每个模式用 1 张卡讲清楚。详细代码在 README.md 对应章节。

⭐⭐⭐⭐⭐ 必抄

1. MCP Server 端实现

Anthropic 的协议，1Panel 自己实现了 server 端（1006 行）。

类比：USB 协议 —— 设备厂商只要按 USB 协议做接口，所有电脑都能用。未来所有 LLM 工具都会走 MCP。
⭐⭐⭐⭐⭐ 必抄

2. Skill 插件系统

每个 Skill 是 {name, description, parameters, handler} 4 元组，动态注册。

类比：Chrome 扩展 —— 不改浏览器代码就能加新功能。1Panel 用户在 Web UI 加 Skill，Agent 启动时读。
⭐⭐⭐⭐⭐ 必抄

3. Context 压缩

对话长了 token 超限，1Panel 用"摘要化 + 截断"两招。

类比：会议纪要 —— 10 小时的会写 1 页纸。前面的细节记不清，但核心结论保留。
⭐⭐⭐⭐⭐ 必抄

4. 多渠道适配

4 套渠道（IM/API/Web/CLI）转同一内部 Message 格式。

类比：快递柜 —— 不管你是顺丰还是京东，放进柜子都是同一个动作。Agent 只认"内部 Message"。
⭐⭐⭐⭐ 抄一半

5. LLM Provider 抽象

OpenAI/Claude/ollama/Hermes 都实现同一 interface，换 LLM 不改业务代码。

类比：数据库驱动 —— JDBC 不关心底层是 MySQL 还是 PG，应用层只调 query。
⭐⭐⭐⭐ 抄一半

6. 多 Agent 协作

Agent A 可以"召唤" Agent B 当工具。LLM 自动选。

类比：公司里你不会就问同事。Agent 也是，找不到工具就调另一个 Agent。
⭐⭐⭐⭐ 慎抄

7. Hermes 集成

1700 行深度集成 Hermes Agent 框架，独立部署要替换。

类比：OEM 发动机 —— 性能好但只能配原厂车。换了车型要重做。
⭐⭐⭐ 参考

8. 工具描述自动生成

每个 Skill 的 description 是 LLM 看到的"使用说明"，提供模板让用户填。

类比：产品说明书 —— 写得好不好，决定用户会不会用。LLM 看到 description 才决定调不调。

053 个反模式（必避）

⚠️ 强依赖

绑定单一 framework

1Panel 强依赖 Hermes 6 个文件 / 1700 行。独立部署要替换。

避坑：你的 AI Agent 平台不要绑死单一 framework，用 LLMProvider interface 隔离。
⚠️ 体验差

本地 LLM fallback 不完整

整套设计假设 LLM 走云端 API。ollama 支持是后补的（仅 120 行）。

避坑：如果你的场景"必须本地"，先想清楚 vLLM / ollama / llama.cpp 的兼容层怎么写。
❌ 单点太多

10000 行 + 18 文件

模块太大，认知负担重。代码 review 痛苦。

避坑：拆成 3-4 个子模块（runtime / skills / channels / context），每个 1000-2000 行，不要照抄架构。
