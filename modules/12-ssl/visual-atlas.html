2HTTP-01 Challenge 验证流程

HTTP-01 原理：CA 服务器主动 GET http://你的域名/.well-known/acme-challenge/<token>，你的 OpenResty 必须能返回正确的 keyAuthorization 才能证明域名是你的。简单但要求 80 端口对外可达 + 不支持通配符。

identifiers: example.com] Req --> Auth[CA 返回 authorizations URL] Auth --> Chal[CA 返回 http-01 challenge
token=abc123] Chal --> Write[lego 在 OpenResty root 目录写
.well-known/acme-challenge/abc123
内容 = keyAuthorization] Write --> Notify[lego 通知 CA: 已就绪] Notify --> Probe{CA 主动 HTTP GET} Probe -->|80 端口可达| Ok[OpenResty 返回 keyAuthorization] Probe -->|不可达 / 404| Fail1[CA 标记 invalid] Ok --> Valid[CA 标记 valid] Fail1 --> Retry([重试 5 次, 失败返回错误]) Valid --> Final[进入 finalize CSR 签发流程] Retry --> End([结束 - 签发失败]) Final --> End2([结束 - 签发成功]) style Probe fill:#1e293b,stroke:#f87171 style Ok fill:#1e293b,stroke:#34d399 style Fail1 fill:#1e293b,stroke:#f87171 style Valid fill:#1e293b,stroke:#34d399

图 2.1 · HTTP-01 验证流程 — 关键是"CA 主动探测你的 80 端口"

HTTP-01 的限制
不支持通配符证书（*.example.com）— 因为通配符无法用单一 HTTP 验证。需要通配符请用 DNS-01。

3DNS-01 Challenge 验证流程

DNS-01 原理：你通过 DNS 厂商的 API（阿里云 / 腾讯云 / Cloudflare 等 10+ 家）添加一条 TXT 记录 _acme-challenge.example.com，CA 服务器去公共 DNS 查询这条 TXT 记录是否正确。**支持通配符**。

图 4.1 · 每天 00:00 续期流程 — 续期阈值（域名 30d / IP 72h）+ SyncSystemSSL 对账机制

SyncSystemSSL 防丢证书
续期时如果 nginx -s reload 失败，DB 已有新证书但磁盘是旧的。SyncSystemSSL 每天 00:00 比对一次，强制把磁盘同步到最新状态。

通配符证书的差别
*.example.com 这种通配符证书只能保护一级子域名（www.example.com ✅, a.b.example.com ❌），且必须用 DNS-01 验证（HTTP-01 不支持）。1Panel 通过 Provider=http 限制不能有通配符（service/website_ssl.go:232）。

EAB 是什么？
External Account Binding = 让 CA 知道"这个 ACME 账户代表哪个用户"。ZeroSSL/Google/FreeSSL 强制要求 EAB，因为它们是"商业 CA"（不像 Let's Encrypt 是公益的）。
