02核心：浏览器 SSH 终端时序

浏览器只能发 HTTP/WebSocket，没法直接发 TCP。所以需要"WebSocket ↔ SSH"双向桥。

sequenceDiagram
    autonumber
    participant U as 用户(浏览器)
    participant B as 1Panel Backend
    participant S as SSH Server(:22)
    U->>B: WebSocket: ssh.connect(host, port, user, key)
    B->>S: TCP: SSH handshake
    S-->>B: SSH version exchange
    B-->>U: WebSocket: connected
    loop 双向数据流
        U->>B: WebSocket: input data (xterm.js keystrokes)
        B->>S: TCP: SSH encrypt + send
        S-->>B: TCP: SSH output
        B->>U: WebSocket: output data (xterm.js render)
    end
图 2：WebSocket 是全双工通道，浏览器发键盘 → 后端加密 → SSH server；SSH 输出 → 后端推 WebSocket → 浏览器渲染

053 个必抄的设计

⭐⭐⭐⭐⭐ 必抄

1. WebSocket ↔ SSH 双向桥

1603 行生产级实现，直接抄能省 1-2 周。

怎么抄：Python 用 paramiko + FastAPI WebSocket，200 行能写完最小版。完整版要加 xterm.js 协议、resize、颜色等细节。
⭐⭐⭐⭐⭐ 必抄

2. 凭据加密存储

设计模式抄，实现用 Vault 替代。

避坑：不要明文存盘，不要用可逆 Base64。1Panel 推测用 AES-GCM + 机器 master key，但你的 Sirius Cloud 用 HashiCorp Vault 更专业。
⭐⭐⭐⭐ 必抄

3. fail2ban jail.local 模板化

跟 nginx.conf 渲染模式一样。

价值：新加监控项只改模板，不改代码。跟 03-website 的 nginx.conf 渲染模式同源。

064 个反模式（必避）

⚠️ 待确认

凭据存储策略

1Panel 说是加密，但具体怎么加密、master key 在哪需要看代码确认。

避坑：你的 Sirius Cloud 凭据管理用 HashiCorp Vault 或 AWS Secrets Manager，不要自己实现。
⚠️ 鉴权漏洞

WebSocket 不鉴权 = 攻击者蹭用

WebSocket 握手后能发 SSH 命令，鉴权只在 HTTP 层不够。

避坑：WebSocket 握手严格校验 JWT + IP 白名单 + 短时 token。
⚠️ 资源浪费

ClamAV 启动慢 + 吃内存

clamav-daemon 启动 ~10 秒，常驻 ~1GB 内存。

避坑：按需启动（clamscan 命令行模式），或用云病毒扫描 API（VirusTotal）。
❌ 分散管理

fail2ban 配置分散 3 个文件

fail2ban.go 230 行 + jail.local 模板 + systemd 服务文件。

避坑：所有 fail2ban 相关配置收 1 个 JailConfig struct。
