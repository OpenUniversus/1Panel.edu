053 个必抄的设计

⭐⭐⭐⭐⭐ 必抄

1. 阈值 + 持续时长

3 种状态机：inactive / pending / firing。

必抄：没有持续时长，CPU 跳到 90% 又掉回 30% 就误报。这是告警系统的地基。
⭐⭐⭐⭐⭐ 必抄

2. 多渠道 Sender 抽象

1 套 interface + 7 个实现。

必抄：Sirius Cloud 通知渠道多，1 套 Sender interface + N 个实现，新增渠道只写 1 个类。
⭐⭐⭐⭐ 必抄

3. 抑制窗口 + 静默期

避免告警风暴 + 维护期不打扰。

必抄：同一问题不重复发。维护期（如 23:00-01:00 DB 升级）所有告警自动静默。

063 个反模式（必避）

⚠️ 单点评估

评估逻辑在单 agent 进程内

多 agent 部署每台各自评估，可能重复触发。

避坑：用中央评估服务（专门 leader 节点评估）+ 分布式锁。
⚠️ 同步发送

同步 HTTP 无重试

Send() 直接 POST，网络抖动就丢。

避坑：用异步队列（Redis/RabbitMQ/Celery）+ 重试 + 死信队列。重要告警丢了代价很大。
❌ 单文件大

alert_helper.go 1019 行

规则匹配 + 状态机 + 抑制 + 静默 + 触发全堆一起。

避坑：拆成 alert_evaluator.go + alert_state.go + alert_suppress.go + alert_silence.go 4 个文件。
