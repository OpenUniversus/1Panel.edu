01配置生成 + 安全 reload 流程

核心思路：永不直接 reload。先把新 conf 写到临时文件，`nginx -t` 测试语法，通过才覆盖正式 conf，再 reload。

043 必抄 + 1 核心

⭐⭐⭐⭐⭐ 必抄

1. 配置安全 reload 策略（核心）

写临时 + nginx -t + 覆盖 + reload。10 行代码价值连城。

适用：所有管配置文件的场景 —— pg_hba.conf / redis.conf / haproxy.cfg。Sirius Cloud 必用。
⭐⭐⭐⭐⭐ 必抄

2. 配置模板引擎

Go template（Go）/ Jinja2（Python）渲染配置，数据驱动。

价值：新增 1 种网站类型不用改渲染代码，只加 1 个模板文件。状态机清晰，不会乱。
⭐⭐⭐⭐ 必抄

3. Let's Encrypt 自动化

HTTP-01 / DNS-01 两种验证，cron 每天检查自动续期。

实现：用现成 ACME 库（Go: golang.org/x/crypto/acme，Python: certbot），别自己实现协议。
⭐⭐⭐⭐ 参考

4. Upstream 负载均衡

多 instance + weight + backup 节点，Sirius Cloud 部署时直接抄。

模板：upstream backend { server x:8080 weight=3; server x:8081 weight=2; server x:8082 backup; }

055 个反模式（必避）

❌ 单文件超 2000 行

website.go 2370 行

3 种网站类型 CRUD 全堆一起。

避坑：拆成 website_default.go / website_proxy.go / website_static.go，每个 500-800 行。
⚠️ 状态机地狱

81 种配置组合

3 类型 × 3 SSL × 3 Auth × 3 LB。代码到处 if-else 拼接。

避坑：先画状态机，用 1 套模板引擎 + 数据驱动，不要堆 if-else。
⚠️ 强依赖 nginx

Nginx 二进制必须在 PATH

整套假设 nginx 命令可用。

避坑：抽象 NginxManager interface（Reload / TestConfig / GetVersion），方便换 Caddy / Traefik。
⚠️ 账号管理分散

ACME 账号 + DNS 账号分 2 个表

website_acme_account.go 89 行 + website_dns_account.go 81 行。

避坑：合并成 CertificateProvider 模型，2 个子表（账号 + 证书）。
⚠️ 操作日志膨胀

website_op.go 跟主表混一起

每改一次网站配置写一条 op log，3 个月后 SQLite 几 GB。

避坑：op log 单独表 + 定期归档（30 天前的移到冷库）。

必抄清单

  1. 安全 reload 模式（safeReloadNginx）—— 10 行代码
  2. 配置模板 + 数据驱动（避免 if-else 拼接）
  3. ACME 自动化 + DNS-01 支持

抄的时候要改

  1. 不用 Nginx（你的 Sirius Cloud 部署用 K8s Ingress / Traefik）—— 抄设计模式不抄实现
  2. 配置管理用 GitOps（conf 文件存 Git，不用数据库）—— 1Panel 为 web UI 方便才存 DB
  3. 多租户隔离 —— 1Panel 假设单机单用户，Sirius Cloud 要按用户隔离
