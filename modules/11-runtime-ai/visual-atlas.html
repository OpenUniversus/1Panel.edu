051 个可借鉴的模式

⭐⭐⭐ 可借鉴

外部进程管理 + 健康检查 + API 暴露

runtime 抽象模式：启停 + 监控 + 诊断。

可借鉴：跟"启动 MySQL 进程"是同一类问题。Sirius Cloud L2 部署 MySQL 时需要：分配资源（CPU/内存/端口） + 启停 + 健康检查 + 暴露连接信息 + 故障诊断。

063 个反模式（必避）

❌ 强依赖

NVIDIA GPU + CUDA 强依赖

整套设计假设有 NVIDIA GPU + CUDA。

避坑：普通 DBaaS 服务器根本没 GPU。Sirius Cloud 不做 AI 推理，整个模块跳过。
⚠️ 单场景

1382 行编排工作量大但服务单一场景

只服务"AI 推理"一个场景。

避坑：不要照抄 1382 行。抽象你自己的"启动进程 + 监控 + 诊断"模式，每个 runtime 100-300 行。
❌ 强依赖 Docker

进程跑在 Docker 容器里

跟 1Panel 其他模块一样，假设 Docker 可用。

避坑：你不用 Docker。用systemd unit 替代（生产推荐）或裸进程 + PID 文件。
